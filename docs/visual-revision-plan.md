# Fleurir LP 画像活用・レイアウト修正計画

2026年10月20日。ユーザーの「元画像が使われていないように見える」「画像が少なく文字中心で見栄えが悪い」という指摘を受けた修正案。今回は計画の作成までとし、LP本体はこの段階では変更しない。

## 1. 現状と設計上の問題

現在のページは、元のsrc/assetsから以下の2枚を使用している。

- line_oa_chat_261019_164017.jpg：店内紹介の横長写真。
- line_oa_chat_261019_163951.jpg：Instagram案内のソファ席写真。

このほかに生成したヒーロー画像を使用している。ヒーローのPC用・スマートフォン用は表示を切り替える同じ役割の画像なので、ページ上の画像枠は実質3か所。

元画像を使う場所がなかったわけではない。初稿では人物・お祝い写真や元のロゴを生かす構成を十分に作らず、文字、罫線、余白を優先した。未採用素材の検討も十分ではなかった。そのため以下の問題が生じている。

1. ヒーロー直後が料金と文章になり、実際のお店の楽しさを見せるタイミングが遅い。
2. 料金、人気メニュー、席数、アクセスが文字主体で続き、画面の変化が少ない。
3. 人物・お祝いの写真がなく、スナックの親しみやにぎわいが伝わりにくい。
4. 元のロゴは直接使わず、コードで組んだ文字とモチーフが中心になっている。
5. 人気メニューは線画装飾と文字が中心で、食べ物の魅力を視覚で伝えられていない。

一方、未使用画像には告知ポスターや文字中心のメニュー撮影画像も多い。すべてを同じ大きさで載せると、文字量と見づらさが増す。内容に応じた配置と扱いを決める。

## 3. 新しい視覚方針

コンセプトは「写真で伝わる、Fleurirの夜」。既存の夜色・淡い水色・ローズは維持し、実店舗の写真と人の表情を主役にする。

- 画像枠は現在の3か所から、主要な表示として8〜10か所程度を目標にする。PC・スマートフォンの切り替え画像や同じ写真の切り抜きを、別の元写真として数えない。
- 写真を見せるセクションでは画面の約50〜60%を画像に使うことを構図の目安にする。全画面に一律の画像比率を課さない。
- 料金やアクセスの実用情報は読みやすさを保ち、紹介文・英語の装飾見出し・余白を整理する。文章量は現状から約25〜30%削減することを目標とする。
- 写真の大きさと縦横比に変化をつける。大きな店内全景、縦長の人物写真、小さなお祝い写真を組み合わせる。
- 写真の直後に長い文章だけのセクションを連続させない。料金・席数・説明を写真に近づけてまとめる。
- 写真の上に文字を置く場合は短い見出しに限定し、顔・商品・店内の特徴を隠さない。

## 5. 料理画像の不足をどう補うか

提供フォルダには、人気5品それぞれを大きく掲載できる単体の料理写真は見当たらない。メニュー表に小さく写る料理画像は、反射・青い色かぶり・解像度の制約があり、切り出して大きくしても主役の写真には向かない。

修正案では、料理イメージ3点の補助生成を提案する。実物の量、器、盛り付けを再現した実写とは扱わず、該当画像の近くに「料理画像はイメージです」と表示する。人気のつまみ名はユーザー提供の5品を維持する。価格・原材料・調理法・セット内容を生成画像から推測して追加しない。

3点の内訳は以下。1枚の画像の切り抜きを使い回す構成にはしない。

1. だし巻き玉子：人気の主役として大きく見せる。
2. 枝豆とポテトフライ：おつまみのにぎわいを見せる。セット商品と誤解されないようにそれぞれの品名を表示する。
3. ホットケーキとアイス：甘いメニューの存在を見せる。実物を再現した盛り付けという説明はしない。

今後、料理の実写真を用意できた場合は、同じレイアウトのまま差し替えられる構成にする。実写真の追加は今回の修正計画を進める必須条件にしない。

## 6. 元画像の扱いと詳細閲覧

- 写真は元データを残し、表示用の派生ファイルを作る。人物の顔や表情を変える生成加工はしない。
- 店内の白いソファ、肌の色、ボトルの光が極端に変わらない範囲で、必要に応じたトリミング・色調整を検討する。
- 実際のロゴ画像は、余白と背景に合う位置で採用する。コードで描き直したロゴだけを主役にしない。
- 元メニューポスターは縦長の比率を保ち、切り抜きで価格や条件だけを落とした画像にしない。
- メニューの拡大表示を実装する場合は、キーボード操作・閉じるボタン・背景のスクロール制御に対応する。
- 求人や期限・実施状況の不明な特典を、現在実施中の内容として追加しない。
- LINEのQRは画像だけの掲載で終わらせず、URLを確認してスマートフォンのボタンと対応させる。

## 7. スマートフォンとアニメーション

- スマートフォンでも、ヒーローの次に実際の人物・店内写真が見える順序にする。
- コラージュはPCでは大小の非対称配置。スマートフォンでは大きな写真と小さな写真2点を組み、極端に小さい3列表示にしない。
- 料金は小さな写真カードに埋め込まず、写真と近接する通常のHTMLで表示する。
- 料理画像はPCでは主役1点＋補助2点、スマートフォンでは主役の大きな1点から順に縦方向で見せる。
- 画像のためだけに横スクロールを強制する仕掛けは入れない。初期状態で主要写真を確認できる。
- GSAPは写真の短い表示と数pxの動きに使う。人物写真を大きく回転・拡大したり、読む操作を待たせたりしない。
- 既存のLenis連携と動きを減らす設定への対応を維持する。
- 画像数が増える分、表示サイズに合うWebPと遅延読み込みを使う。ヒーロー直下の実写真は早めに表示し、画像の縦横寸法を確保してずれを防ぐ。

## 8. 作業順とレビューのポイント

1. 元画像と掲載場所を対応させ、歓迎コラージュ・料金と店内・料理メニューの3ブロックを静止状態で具体化する。
2. 補助の料理画像3点を生成し、実写真と並べた時の色・明るさを確認する。
3. 写真を主役にした全体構成へ組み直し、重複する説明と過大な余白を減らす。
4. 元ロゴ、メニュー拡大表示、Instagram、LINEの確認済み導線を反映する。
5. PC・スマートフォンで写真の大きさ、顔の切れ、文字の読みやすさ、表示速度を確認し、最後に動きを調整する。

完成判定：

- 元画像を使用していることが、歓迎写真・店内写真・ロゴからすぐに分かる。
- ヒーロー直下で実店舗の雰囲気と人の表情が伝わる。
- 人気メニューが文字を読む前に視覚でも伝わる。
- 料金・アクセスの探しやすさを維持し、画像内の小さな文字だけに情報を依存しない。
- 同じ写真の繰り返しや、告知ポスターの大量掲載で水増ししない。
- 1階の正式URLと現在の電話・地図導線を維持する。
